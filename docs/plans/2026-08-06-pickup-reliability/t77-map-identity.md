## Two things that shape the fix

### The codes are a family: `t<digit><digit>`

Nine of ten follow it — `t11`, `t21`, `t22`, `t24`, `t26`, `t32`, `t33`,
`t34`, `t36`. That is a **pattern the registry can match**, rather than a
list somebody has to keep topped up as new maps are met. Anchoring to the
code pattern is also the R144-compliant form: it survives a season
renumbering, which a hardcoded kind list does not.

**VERIFIED, 2026-08-06.** The whole code table holds exactly **30**
`t\d\d` entries, kinds **737–788**, and nothing else uses the form:

    t11 t12 t13 t14 t15 t16   (737 738 739 768 776 780)
    t21 t22 t23 t24 t25 t26   (740 741 742 743 744 775)
    t31 t32 t33 t34 t35 t36 t37 t38 t39   (745..751, 759, 754)
    t41 t42 t43               (752 765 777)
    t51 t52 t53               (785 786 788)
    t61 t62                   (755 756)
    t99                       (753)

All ten sampled maps fall inside it and no non-map item collides, so the
pattern is safe to match on. It also implies **30 known map kinds, of
which we have only seen 9** — precisely why matching beats listing.

### Kind 810 has no code at all

`config/item_codes.toml` was generated by T42 and holds 800 entries;
810 is past its end. So either the table predates this map or T42's
sweep was bounded short. **Do not guess it** — that is R144's whole
point. Two honest options:

1. re-run T42 to regenerate the code table and pick 810 up properly;
2. record 810 as an observed-but-unnamed member with its provenance
   (T77, 2026-08-06), which is what the drill log already carries.

The kinds are **not contiguous** (737…810 with gaps), so an id *range*
is not available as a shortcut either.

## Consequence for P5

The registry needs the whole set. Recommended shape:

- match maps by **code pattern** `t\d\d` (after verifying no
  collisions), so future maps are covered automatically;
- carry kind **810** as an explicit observed member until T42 is re-run;
- treat maps as `no_drop` **and** `no_transfer` — a map's right-click
  consumes/opens it, which is the tome's property, and the cleanse's
  ctrl+right-click is exactly the gesture that loses its modifier.
